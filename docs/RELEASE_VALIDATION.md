# v0.2.0 验收记录

本记录对应 StudyBridge（笔记桥）v0.2.0 发布候选。更名后的 EXE 已在项目迁移后的目录单独完成 Windows 验收；校验值见同一 Release 的 build-info.json。

验证日期：2026-10-12。目标环境：Windows 11 x64，本机 Node.js 24。软件要求 Node.js 22+；AI 功能另需用户安装 Codex CLI。本版 EXE 不打包这些外部运行时。

## 已完成

- 完整自动化回归 **155 项通过，0 失败、0 取消、0 跳过**，包括真实 Edge 浏览器测试。按两个测试文件并发执行，避免浏览器实例争抢资源。
- 原文/译文映射、笔记、圈画、导入导出、公式、代码块、截图以及 Codex 协议模拟测试。
- README 配图固定白名单、真实 PNG 签名与大小限制、目录链接拒绝，以及公开仓库源码/个人图片排除规则。
- 资料库、首页缩略图、搜索、课程文件夹、项目设置、PDF 导入及补译文、旧阅读深链与窄屏布局。
- 笔记目录调整等待正在保存的内容，复制核验后更新配置，保留原文件；目录冲突或配置提交失败时保留原指针。
- AI 对齐使用独立文字会话，不改笔记与问答；候选需确认，无效页码、无文字扫描件及过期结果被拒绝。快照读取期间也可取消，详情映射与版本来自同一快照。
- 未提交的课件/工作区/文件夹设置及页码审核会阻止退出，保留输入；迟到的详情请求不会覆盖退出窗口。
- 数据目录租约避免 EXE 与开发服务重复写入，陈旧锁可恢复；原生工作区选择控制需要独立随机凭据。
- 两个浏览器标签页分别保存后退出；模拟保存失败时保留编辑并取消退出。
- 后台标签即使冻结超过心跳间隔，也不会被正常退出跳过；未收完整的请求体可取消，完整请求的慢写盘仍等待完成。
- v0.2.0 已由用户实际完成原生目录选择、中文名称工作区创建并打开默认 Chrome 资料库；工作区名称、实际路径、空项目列表、服务健康与最终 EXE 版本一致，成功位置已记忆。
- 既有 v0.1.0 合成工作区使用 v0.2.0 的新内容缓存启动后，中文笔记与状态文件字节保持不变；移动/替换 EXE 后的状态也已验证。
- 源码与公开产品文档分别通过白名单生成；常见敏感信息模式扫描未发现匹配。检查不等同于完整安全审计。

Windows 实际集成测试 **9/9 通过**：

| 场景 | 结果 |
| --- | --- |
| PATH 缺少 Node | 明确提示 Node.js 22+，不启动服务，不自动下载 |
| 检测到模拟 Node 18 | 拒绝过旧版本并提示要求 |
| 中文/空格目录正常启动 | 使用指定的本机 Node，仅 127.0.0.1 监听 |
| 同工作区重复启动 | 复用原实例，没有第二个写入进程 |
| 保存后正常退出 | 笔记落盘，Node 和模拟 CLI 的子孙进程全部退出 |
| 指定端口已占用 | 改用可用端口，原占用程序不受影响 |
| 移动或替换 EXE 后重启 | 继续使用原数据，文件字节保持一致 |
| 只终止本应用启动器 | Windows Job 清理其 Node、CLI 和子孙进程 |
| 只终止本应用 Node | 启动器结束并清理其 CLI 子孙进程 |

最终集成测试遗留进程数为 0。最终附件体积以对应构建的 `build-info.json` 为准。测试脚本已修正启动早期读取进程身份的时序问题，仅在确认 PID、启动时间和路径后才执行异常终止测试。

## 验证边界

- 自动化使用合成项目与受控 Codex 进程夹具，不读取个人凭据、不调用真实账号模型，未验证本版 AI 对齐的真实云端生成质量。
- 已在当前 Windows 11 机器验收，尚未在洁净虚拟机、其他 Windows 版本或 ARM64 设备上验收。
- EXE 尚未进行 Authenticode 代码签名。
- 正常退出等待保存；明确确认的强制退出、进程崩溃或断电可能丢失尚未提交到服务的编辑。
- 切换前检查目标目录与运行资源。若保存完成后目标启动仍遭系统阻止，旧数据已经保存，可重新打开原工作区。
- 完整的原生 A → B 工作区切换仍未完成人工端到端验收；控制协议、跨标签保存屏障及原生路径预检已有自动化覆盖。新建与实际启动已单独验证，不将其等同于完整切换验证。

最终附件的文件体积、外部依赖要求和 SHA-256 见 Release 中的 `build-info.json` 与 `SHA256SUMS.txt`。
